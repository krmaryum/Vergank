# AZ-104 Day 02 — English Summary Report

## Class overview
The class explores why organizations moved from traditional on-premises infrastructure to virtualization and public-cloud consumption, using a diamond-company scenario and hands-on Azure account preparation as anchors.

## Learning objectives
1. Explain why organizations need servers, networking, DNS, DHCP, AD DS and application services.
2. Plan a basic on-premises data center with redundant power, cooling and capacity.
3. Distinguish CAPEX from OPEX using the instructor's illustrative costs.
4. Explain DR sites, replication, RTO and RPO.
5. Explain virtualization benefits and limits, Type 1/Type 2 hypervisors, and server consolidation.
6. Compare public, private, hybrid and multi-cloud choices.
7. Explain pay-as-you-go, scaling, reliability and cloud risks.
8. Compare IaaS, PaaS and SaaS operational responsibility.
9. Describe Azure free-account considerations and region selection.

## Practical classroom scenarios
- Owners Nadeem and Khalid hire an infrastructure administrator to design a diamond-business IT environment.
- The administrator requests a data center, redundant facility services, server capacity and a secure network.
- Illustrative initial CAPEX is ₹1 crore, with illustrative monthly OPEX of ₹20 lakh.
- Delhi is a primary site and Bengaluru the example DR site.
- A VM or physical server outgrows a 16 GB RAM / 4-core allocation.
- An airline ticket replaces aircraft ownership as the cloud pay-as-you-go analogy.
- The instructor navigates Azure free-account and region pages for upcoming practice.

## Key takeaways
- Cloud consumption changes who owns and operates equipment; it does not eliminate physical infrastructure.
- Moving to cloud does not remove the need for architecture, security, identity, cost controls or DR.
- Recovery time (RTO) and maximum tolerable data loss (RPO) must be separately defined.
- Cloud types and cloud service models answer different questions.
- Billing and free tiers change; verify current provider terms.
